# Мини-приложение MAX: «Сыры&Колбасы» — каталог и доставка

Статичный фронт (HTML/CSS/JS, без сборки) + Google Таблица с Apps Script в роли бэкенда.
Оплата онлайн пока не подключена: заказ уходит владельцу, оплата при получении или переводом.

## Что внутри

| Файл | Зачем |
|---|---|
| `index.html`, `styles.css`, `app.js` | Выбор способа (доставка / самовывоз / онлайн-каталог), шапка, баннеры, плитки категорий, корзина |
| `checkout.js` | Оформление: доставка/самовывоз, зоны, слоты времени, статусы заказа |
| `config.js` | Название, тексты способов получения и подсказки, баннеры, часы работы, URL бэкенда |
| `demo-data.js` | Тестовое меню для демо-режима |
| `Code.gs` | Бэкенд для Google Apps Script |

## Как PWA (без MAX)
Приложение уже работает как PWA: после загрузки на https-хостинг его можно открыть в браузере и
установить на телефон («Добавить на главный экран»). Файлы: `manifest.webmanifest`, `sw.js`, иконки `icon-*.png`.
- Загрузите на хостинг **все файлы** из архива, кроме `Code.gs` и `README.md`.
- После правок сайта в `sw.js` поднимите `VERSION` (`v1` → `v2`), чтобы у клиентов обновился кэш.
- Вне MAX нет автоматической подписи пользователя: для приёма заказов поставьте `ALLOW_NO_AUTH` = `true`
  в свойствах скрипта. Тогда заказ может отправить любой, у кого есть ссылка, поэтому проверяйте заказы по телефону.
- Уведомлений о смене статуса не будет (их шлёт бот MAX), клиент видит статус в приложении по ссылке заказа.
- Позже можно подключить MAX: тот же сайт указывается в настройках бота, код менять не нужно.

## Посмотреть локально (демо-режим)

```
python3 -m http.server 8000
```

Откройте http://localhost:8000. Пока `API_URL` в `config.js` пустой, работают тестовые данные,
заказ не уходит никуда, статусы в демо сами меняются каждые 20 секунд.

## Запуск по шагам

### 1. Хостинг
Загрузите все файлы, кроме `Code.gs` и `README.md`, на хостинг с `https`: GitHub Pages, VK Cloud
или Yandex Cloud. MAX открывает только `https`-ссылки (латиница, цифры, точка, дефис).

### 2. Таблица и бэкенд
1. Создайте Google Таблицу. Расширения → Apps Script → вставьте содержимое `Code.gs`.
2. Выберите функцию `setup` и запустите её (разрешите доступ). Появятся листы
   `Categories` (группа, название, эмодзи/фото плитки), `Catalog`, `Zones`, `Pickup`, `Orders` с примерами и выпадающим списком статусов.
3. Настройки проекта → Свойства скрипта, добавьте:
   - `BOT_TOKEN`: токен бота из MAX для партнёров (нужен для проверки пользователей и сообщений);
   - `BOT_USERNAME`: имя бота без `@` (для ссылки на статус заказа в сообщениях);
   - `OWNER_USER_ID`: ваш ID в MAX, куда придут новые заказы (см. шаг 5);
   - `ALLOW_NO_AUTH` = `true` только на время тестов в браузере, потом удалите.
4. Развернуть → Новое развёртывание → Веб-приложение. «Выполнять от имени»: я. «Доступ»: все.
   Скопируйте URL и вставьте в `API_URL` в `config.js`, загрузите `config.js` на хостинг заново.

Меню, зоны доставки и точки самовывоза правятся прямо в таблице, приложение подхватывает
изменения при следующем открытии. Колонка `available` = `false` помечает товар «Нет в наличии». Название в колонке `category` у товара должно совпадать с `name` в листе `Categories`. Колонка `image` — ссылка на фото (https).

Цвет бренда — переменная `--accent` в начале `styles.css`.

### 3. Бот и мини-приложение в MAX
Подключение доступно резидентам РФ: юрлицам, ИП и самозанятым. На
[платформе MAX для партнёров](https://business.max.ru/self): Чат-боты → ваш бот → ⋮ → Настройки,
вставьте URL приложения, выберите вид кнопки и сохраните.

### 4. Статусы заказов
Владелец меняет колонку `status` в листе `Orders`. Клиент видит статус в приложении
(обновляется раз в 15 секунд), а бот отправляет ему сообщение о смене статуса.
Сообщение дойдёт, если у клиента есть диалог с ботом.

### 5. Как узнать свой ID для `OWNER_USER_ID`
Оформите тестовый заказ из MAX со своего аккаунта (при `ALLOW_NO_AUTH` = `false`
заказ принимается только из MAX). В листе `Orders` колонка `userId` покажет ваш ID.

## Что важно знать
- Цены и состав заказа пересчитываются на сервере, подмена с клиента не пройдёт.
- Подпись пользователя (`initData`) проверяется по алгоритму из документации MAX.
- Слоты времени считаются по часам телефона клиента, часы работы задаются в `config.js`.
- Лимиты Apps Script (в том числе на число запросов) хватает для небольшой доставки; при росте нагрузки
  бэкенд стоит заменить на обычный сервер.
- Онлайн-оплата (например, ЮKassa) потребует серверной части; её можно добавить следующим этапом.
